# TapRelay Android 端「按钮布局」概括（供 UI/UX 优化参考）

> 项目定位：TapRelay 是一个「PC 端 AI Agent（WorkBuddy / 豆包 / Claude 等）任务状态 → 实时推送 Android 手机」的通知中转系统。手机端是**纯接收 + 远程处置**的轻量客户端，本身不做创作，所有按钮都围绕「连接管理」「消息处置」「PC 远程控制」三类诉求。
>
> 技术栈：Kotlin + Jetpack Compose（主界面 / 浮窗 / 全屏提醒）+ 少量 XML（系统通知渠道）。按钮原子组件为自绘 `PlainButton`（规避 Material3 白底 bug），variant 有 `PRIMARY`（实心主按钮）、`SMALL`（紧凑小按钮）。

---

## 一、主界面（App 内，`MainScreen.kt`）

整体是单列纵向滚动：标题栏 → 连接状态卡片 → 消息历史列表。

### 1. 标题栏
| 元素 | 类型 | 说明 |
|---|---|---|
| 任务通知（标题文本） | 文本 | 非按钮 |
| 「待处理 N」胶囊 | 状态展示 | 非按钮，随 waiting 消息数变化 |
| 设置 / 主题图标 | 图标按钮 | 打开设置 |
| 个人项目图标 | 图标按钮 | 打开「个人项目」弹窗 |

### 2. 连接状态卡片（`CompactConnectionStatus`）
首页只保留**摘要**；地址、开关与 PC 电源等配置/低频控制全部移入设备管理面板（见第 4 节）。
- 状态行：状态圆点 + 设备名称 + 右侧 `已连接/未连接` 状态文本（整块可点 → 打开设备管理）
- 右侧：`设备管理` 按钮（`PlainButton.SMALL`）
- 仅当 `未连接` / `重连中` 时追加一行（各 `weight(1f)`）：`重新连接`（PRIMARY）/ `扫码连接`（SECONDARY）

> **历史布局（已移除）**：主屏曾有「3 行 8 按钮」矩阵——
> Row1 连接/断开/扫码连接，Row2 隐藏 IP/权限/省电，Row3 睡眠/关机，
> 定义在 `MainScreen.kt` 的 `ConnectionPanel`（早已无人调用的死代码，已删除）。
> 旧痛点（等分排布、无层级、误触）已随迁入设备管理面板并按语义分区而解决。

### 3. 消息历史区
- 筛选栏（单行 Row）：
  - 左侧：`时间` / `应用` 模式切换胶囊（listMode 切换）
  - 右侧弹性留白后：`N 条未读`（高亮文本）+ `全部已读` 小按钮（仅未读>0 时显示）+ `清空历史` 小按钮（列表非空时可用）
- 消息卡片（每条右侧动态按钮）：
  - waiting 且带 requestId：`允许` / `拒绝`（远程审批）
  - 可停止且带 sessionId：`停止`（远程停止）
  - 普通消息：`关闭`

> 当前痛点：右侧按钮随状态变化，但缺乏统一视觉规范；「继续」与「允许/拒绝」语义不同却同处卡片右侧易混淆。

### 4. 设备管理面板（`DeviceControlSheet.kt`，BottomSheet）
由首页「设备管理」按钮或点击状态卡片唤出；连接配置与低频控制的集中入口。
面板内按语义分成四个分区：

| 分区 | 行（上→下） | 交互意图 |
|---|---|---|
| 设备信息 | `PC 地址（IP / 域名）` 输入框（`默认端口：1122`） | 编辑连接地址 |
| | `设备名称` 输入框（最多 40 字） | 首页显示名 |
| | `扫码更新地址`（按钮） | 扫码写入地址 |
| | `历史地址` + `查看`（SMALL） | 进入历史地址列表 |
| 连接管理 | `消息通道` + 状态详情 + `连接` / `断开连接` | 连接与断开 |
| 系统设置 | `权限状态` + `检查权限`（SMALL） | 通知 / 悬浮窗 / 后台权限向导 |
| | `省电模式`（Switch） | 动效开关 |
| | `隐藏地址`（Switch） | 地址脱敏（含历史列表与系统前台通知） |
| PC 电源 | `让 PC 睡眠` / `关闭 PC` | 经 WebSocket 下发电源指令 |

**历史地址子页**：在面板内切页（不是再叠一层弹窗），列表按最近使用倒序、最多 10 条，
显示相对时间与「当前」标记；点击条目即回填地址 + 自动连接 + 关闭面板。
脱敏开启时输入框与列表条目同样脱敏；地址栏在脱敏状态下 `readOnly`，
避免把 `1**.1**.5.6` 这类掩码串当成真实地址写回连接配置。

## 二、个人项目弹窗（`PersonalProjectsDialog.kt`）
- 列表项（每卡底部）：`直达`（打开链接，实心主按钮）+ `复制`（复制 URL，描边按钮）
- 顶部：关闭弹窗的 X 图标按钮
- 已删除无意义的「GitHub 项目」底栏文本与标题下域名

---

## 三、通知面（浮窗 / 全屏提醒 / 灵动岛 / heads-up）
四类通知形态共享同一份消息模型，按钮逻辑一致（`OverlayCards.kt` / `FullScreenAlertActivity.kt`）：

| 消息状态 | 页脚按钮 | 说明 |
|---|---|---|
| 普通 | 关闭 / 全部关闭 | 关闭单条 / 清空全部浮窗 |
| waiting + requestId | 允许（主）/ 拒绝 | 远程审批，经 WebSocket 回传 PC 处置 |

- 灵动岛（`Island.kt`）、临时 heads-up（`TransientTaskHeadsUp.kt`）为轻量展示，一般不带操作按钮，点击跳转 App。

---

## 四、首次权限向导（`PermissionCheckScreen.kt`）
- 逐项权限检查（通知 / 悬浮窗 / 电池优化等），每项一个状态指示
- 底部：`下一步` / `完成`（全部授予后启用）

---

## 五、其它交互入口
- 扫码连接窗（`ConnectionQrForm.cs` 对应手机扫码端）：手机端仅负责扫码解析，无额外按钮。
- 设置页：开关类控件为主，非按钮密集区。

## 六、建议优化方向（供其它智能体参考）
1. **连接卡片分层**：将「高频连接操作（连接/扫码）」与「危险操作（睡眠/关机）」分组并区分颜色/间距，降低误触。
2. **按钮语义统一**：「停止（远程控制）」与「允许/拒绝（远程审批）」应使用不同色系或图标，避免同处卡片右侧混淆。
3. **矩阵宽度利用**：8 个按钮等分 3 行，可考虑 2 列网格或按功能分组卡片，提升可读性与单手可达性。
4. **待处理胶囊权重**：「待处理 N」与标题栏视觉权重可再平衡，引导用户优先处理 waiting 消息。
5. **通知面按钮一致性**：浮窗 / 全屏 / 灵动岛的按钮文案与命中区应保持一致，减少跨形态认知负担。
