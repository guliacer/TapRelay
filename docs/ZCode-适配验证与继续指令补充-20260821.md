## 2. 待处理（waiting）状态：本轮补全（关键）

### 2.1 现状与缺口

首版适配（2026-07-31）只覆盖了 ZCode 的**终态**（`turn.completed`/`turn.failed`），未覆盖"等待用户操作（waiting）"。ZCode CLI JSONL 中，等待真人回复的唯一可靠信号是 **`AskUserQuestion`** 工具（体现为 `tool.call.started` / `tool.permission.resolved`，`context.toolName=="AskUserQuestion"`）。

### 2.2 关键研判：自动模式会误报

真实 ZCode 日志实测，`AskUserQuestion` 在 **`yolo` 模式**下会被 ZCode 自行代答，毫秒级自动结束（`tool.call.started` → `tool.permission.resolved decision=modify` → `tool.call.completed`，全程约 5ms）。若在 `tool.call.started` 时立即广播 waiting，就是**误报**。

因此沿用 claude-haha 权限卡的**宽限期复核**模式：

1. `tool.call.started`/`tool.permission.resolved` 且 `toolName==AskUserQuestion`、非自动模式 → **登记**待确认项（不立即广播）。
2. `tool.call.completed`/`tool.call.failed` → **取消**登记。
3. 超过 `PermissionWaitGracePeriod`（90s）仍未结束、且对应日志无新写入、且无完成/失败事件 → 才**广播 waiting**。
4. `yolo`/`bypassPermissions` 自动模式或 `decision∈{allow,modify}` 已代答 → **忽略**，绝不广播。

按代码库既有"静态解析器 ↔ 运行时监控"分离惯例，将**判定**逻辑抽为纯静态方法，运行时只做登记/取消/按周期复核：

| `pc-app/AgentCompletionMonitor.cs` | 新增 `_pendingZCodeWaits` 登记表、`ProcessZCodeWaitingLine`（登记/取消）、`TryFireZCodeWaits`（每扫描周期按 90s 宽限期复核广播）、`PendingZCodeWait` 载体类；`ProcessZCodeLine` 与扫描循环接入 |

### 5.4 补充修复：通知卡片缺任务日志（P084，2026-08-22）

用户在真机确认"卡片只显示任务已完成，没展示通知日志"。排查定位到 `ZCodeSessionReader.TryResolveTaskLog` 取不到助手正文的根因：

1. **LIKE 模式与紧凑 JSON 不匹配**：真实 `part.data` 是紧凑 JSON `{"type":"text","text":...}`（冒号后无空格），而读者用 `'"type": "text"'`（带空格）粗筛 → 实测同一会话 0 命中（紧凑模式 229 命中）→ 正文恒空。
2. **未按 turn 过滤**：同会话多 turn 时按整个会话取最后一条，会取到其它轮次，与该 turn 的通知不符。

修复：`TryResolveTaskLog` 改为 `part JOIN message` 联查，LIKE 修正为紧凑 `'"type":"text"'`，用 `json_extract(role)='assistant'` 过滤助手正文，并新增可选 `turnId`（`json_extract(anchor.turnId)`）按 turn 精确取该轮最后一条助手正文；`ApplyZCodeSessionContent` 传入 turnId。单测改为紧凑 JSON + 多 turn 数据，断言全局/按 turn 两路都正确；167 项全绿，`package-pc.ps1` 重建重启生效。

### 5.5 补充修复：任务名称字段（P084 收尾，2026-08-22）

修复日志后复核发现**任务名称**仍显示兜底占位 `任务 turn_…` 而非真实会话标题。根因：解析器用 `ResolveFolderFirst(title,cwd,taskId,"")` 预填 `ProjectName`，取不到标题时回退成 taskId 派生的占位名，而 `ApplyZCodeSessionContent` 只在 `ProjectName` 为空时才覆盖，真实标题盖不掉占位名。方案：真实标题解析成功时，只要现有 `ProjectName` 为空、或为「任务 」前缀占位、或已含该标题（大小写不敏感），就用真实标题覆盖。验证：167 项全绿，`package-pc.ps1` 重建发布（08:11）、`/health` ok、新进程 08:11:37 启动。至此 ZCode 卡片四字段（任务名称/任务日志/任务耗时/任务消耗 token）均以真实会话数据填充。

### 5.6 补充修复：通知标题随当轮对话变化（2026-08-22）

用户反馈"任务没有跟随每次对话显示，一直显示会话最上方的（标题固定为会话名）"。定位：手机卡片**标题始终等于会话名**（如「查看项目规则」），而同一会话的多轮（turn）共用该固定标题，无法区分"这次在做什么"。日志正文其实早已随轮切换，问题仅在标题。方案：新增 `ZCodeSessionReader.TryResolveTurnQuery(sessionId, turnId, out query)`，按 `anchor.turnId` 取该轮**第一条真实用户提问**（过滤 TodoWrite 提醒、userselect 快照等系统注入文本）；`ApplyZCodeSessionContent` 将该提问浓缩到 28 字符作为标题主体，会话名放括号作归属，格式为「进行测试 任务已完成（查看项目规则）」。`projectName` 仍保留稳定会话名，手机端据此归类/分组同会话的多轮。验证：167 项全绿（新增 turnA 按轮取「请修复登录」、全局回退两断言）；真实库 `turn_4f2205d9` 返回「进行测试」；`package-pc.ps1` 重建发布（08:46）、`/health` ok、新进程 08:46:44 启动、手机已连接。
