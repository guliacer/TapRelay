# TapRelay PC 端“非对称轻量工作台”视觉重做设计

## 1. 背景与目标

当前 PC 端功能已经覆盖服务启停、手机连接、二维码、测试通知、通知应用、公网隧道、运行记录和主题切换，但首页仍然以多张等权卡片承载信息。视觉重点不够明确，常用的连接操作和低频的管理信息混在同一层级中。

本次改造采用“非对称轻量工作台”方向：保留现有功能和数据链路，把手机连接作为首页第一视觉重点，减少厚重边框，统一主窗口与弹窗的视觉令牌，并提供一个面向常驻托盘用户的简洁视图。

## 2. 范围与不变项

### 包含

- PC 主窗口首页的布局、层级、间距、颜色、按钮和状态展示。
- 二维码、网络设置、应用选择、个人项目等 PC 弹窗的统一视觉框架。
- 主窗口浅色/深色主题的视觉令牌统一。
- 简洁视图的显示切换和本地 UI 状态记忆。
- 键盘焦点、无障碍名称、状态文本和现有功能入口的视觉增强。

### 不包含

- 不改变 `1122` 服务端口、HTTP/WebSocket 协议或 Android 通信行为。
- 不改变通知应用识别、隧道检测/修复、二维码数据格式和 ComfyUI 业务逻辑。
- 不新增公网服务、账号、鉴权、云端链路或新的手机可见端口。
- 不移除现有深浅色主题、托盘行为、日志收集和窗口关闭语义。

## 3. 信息架构

### 3.1 标准视图

主窗口按以下顺序组织：

1. **顶部状态栏**：TapRelay 品牌、服务状态、端口、手机连接数；右侧保留二维码、主题和更多入口。
2. **手机连接主模块**：使用最大视觉权重展示当前连接地址、复制、二维码、启动服务、停止服务和网络设置。
3. **次级工具区**：左侧为发送测试通知，右侧为通知应用和自动检测/应用选择。
4. **运行记录抽屉**：默认折叠为一行摘要，显示级别、最新日志和条数；点击后展开完整日志。

主模块采用非对称布局：手机连接区域占更大面积，服务控制和公网状态作为右侧次级信息，避免所有卡片等权。

### 3.2 简洁视图

简洁视图面向长期驻留桌面的用户，仍在同一个主窗口内切换，不新开窗口。保留：

- 服务状态与端口。
- 当前手机连接地址。
- 二维码、复制、启动/停止服务。
- 发送测试通知。
- 最近一条运行记录。

通知应用详细列表、公网配置、个人项目和完整日志收进“更多”或对应抽屉入口。切换结果写入现有 UI 状态存储，重启后恢复上次视图。

## 4. 视觉令牌

### 4.1 浅色主题

| 语义 | 用途 | 目标色 |
| --- | --- | --- |
| Background | 页面背景 | 暖白、低饱和绿灰 |
| Surface | 主模块和弹窗表面 | 白色 |
| InputSurface | 输入框和日志区域 | 极浅绿灰 |
| Accent | 品牌、二维码和焦点 | sage 绿 |
| Success | 服务运行、连接成功 | 稳定绿 |
| Warning | 隧道异常、需关注 | 橙色 |
| Danger | 停止服务、错误 | 红色，仅用于语义反馈 |
| TextPrimary | 标题和主要数据 | 深绿灰 |
| TextSecondary | 说明和辅助信息 | 中性灰绿 |
| Border | 细分隔线和输入框描边 | 低对比绿灰 |

### 4.2 深色主题

深色主题使用深灰绿背景和稍亮的 sage 高亮，保持与浅色主题相同的语义色映射；不使用纯黑背景或霓虹高饱和色。所有状态必须同时保留文字和颜色/形状表达，不能只依赖颜色。

### 4.3 尺寸规则

- 页面外边距：24px。
- 主模块内边距：20px。
- 模块间距：16px。
- 控件间距：8px 或 12px。
- 主输入框和主按钮高度：40px。
- 普通按钮高度：32px。
- 主模块圆角：14px。
- 输入框与按钮圆角：10px。
- 主标题、区块标题、辅助说明按固定字号层级排列，禁止单独为某个页面临时加字号。

## 5. 组件与交互

### 5.1 连接模块

- 地址为模块中的最大信息，使用等宽字体并保留横向滚动/巡航行为。
- “二维码”和“复制”是同一组连接动作；二维码作为高权重主入口，复制作为次级入口。
- “启动服务”使用主按钮；“停止服务”继续使用危险描边按钮。
- 公网隧道状态以状态徽章展示；“检查公网”和“修复隧道”保留在二维码/网络相关入口中，不改变现有功能位置语义。

### 5.2 测试通知模块

- 输入框和“发送测试”保持同一行对齐。
- 发送中、成功和失败分别使用禁用态、成功色和错误色反馈。
- 不增加额外确认对话框，避免打断快速测试。

### 5.3 通知应用模块

- 应用使用紧凑芯片/标签展示启用状态。
- 自动检测和应用选择放在标题右侧，保持与模块标题同一基线。
- 应用较多时继续使用现有换行和滚动逻辑，视觉上减少每项的边框重量。

### 5.4 运行记录

- 折叠态继续显示级别点、最新一行和条数。
- 展开/收起增加清晰的方向提示和悬停反馈。
- 日志正文、滚动条和空状态沿用统一主题色，不改变现有日志内容和顺序。

### 5.5 弹窗统一

二维码、网络设置、应用选择、个人项目等弹窗统一：

- 标题区：标题、简短说明、必要时的状态徽章。
- 内容区：统一 20–24px 内边距和 16px 分组间距。
- 底部操作区：主操作靠右，取消/关闭使用次级按钮；危险操作保持描边。
- 所有按钮使用 `UiButtonStyler`，不再在单个窗体里定义独立颜色和圆角。

## 6. 实现边界

优先复用现有的 `UiTokens`、`UiButtonStyler`、`VisualCardPanel`、`StatusStripPanel`、主题切换和布局重算机制。主窗体布局集中在 `MainForm.cs`，通用尺寸与颜色集中在 `UiTokens.cs`，弹窗只消费统一令牌，不复制颜色常量。

简洁视图只改变控件可见性和布局，不销毁控件、不切换服务状态、不改变数据订阅，避免窗口切换导致日志、连接或定时器丢失。

## 7. 验收标准

- 默认窗口打开后，用户能在首屏一眼找到服务状态、手机地址和二维码入口。
- 启动、停止、发送测试、复制地址、主题切换、应用检测、日志展开等既有操作行为不变。
- 标准视图和简洁视图在 100% 与高 DPI 下均不出现控件重叠、文字截断或按钮越界。
- 浅色和深色主题下，标题、说明、输入框、按钮、状态色和弹窗风格一致。
- 所有状态仍有文字表达，并保留键盘焦点和无障碍名称。
- 发布前执行 `dotnet build`、`git diff --check`，再通过 `tools/package-pc.ps1` 更新固定发布目录并验证 `/health`。
