# TapRelay Android 悬浮通知体系优化需求

> 本文件整合 Android 悬浮通知体系的三项优化需求：消息弹窗布局、流媒体胶囊主题化、胶囊动态效果与省电开关。供实施智能体直接执行。

---

## 一、背景：三档悬浮体系

```
Compact（贴摄像头孔圆点）→ Peek（流媒体胶囊）→ Expanded（消息弹窗）
```

- 同一个 `TYPE_APPLICATION_OVERLAY` 窗口内连续形变，禁止 `removeView/addView` 换窗口
- 新消息默认进入 **Peek 流媒体胶囊**；点击 Peek → 展开 **Expanded 消息弹窗**
- 流媒体胶囊与消息弹窗是同一体系的**关联档位**，优化时需保持形变衔接与视觉一致

| 档位 | 形态 | 说明 |
|---|---|---|
| Compact | 贴摄像头孔的深色圆点（18–36dp），仅状态色点 + 脉冲动画 | 已禁止作为新消息默认入场 |
| Peek | 摄像头正下方横向胶囊（高 28–36dp，宽按内容 120~220dp，上限屏宽 72%） | 新消息默认入场档，整颗可点，点击推进到 Expanded |
| Expanded | 完整消息卡片层叠（最多 5 张） | 消息弹窗，本次任务一的优化对象 |

---

## 二、总原则：所有消息弹窗类型自动跟随深浅色模式

**APP 上所有消息弹窗类型都必须自动跟随软件深浅色模式（LIGHT/DARK）切换颜色，不允许任何弹窗类型存在恒色。**

### 现状盘点

| 弹窗类型 | 是否跟随主题 | 说明 |
|---|---|---|
| 主界面（MainScreen） | ✅ 已跟随 | `appColors` 语义令牌 |
| 消息弹窗（Expanded 悬浮卡片） | ✅ 已跟随 | `appColors.OverlaySurface` 等 |
| 全屏提醒（FullScreenAlertActivity） | ✅ 已跟随 | `appColors.Surface/TextPrimary` 等 |
| **流媒体胶囊（Peek 胶囊）** | ❌ **恒深色** | `AppTokens.IslandBackground = #0A0A0B`，注释明写"恒深色，不随深浅色模式变化" |
| **Compact 贴孔圆点** | ❌ **恒深色** | 同 Island 系列背景 |
| **系统通知自定义视图（RemoteViews）** | ❌ **硬编码色** | `notification_*_collapsed/expanded.xml` 写死 `#FFFDFB` 浅底、`#FFFFFFFF` 白字、`#1B2A3C` 深字、`#1BAA59` 绿等，构建时不感知主题 |

### 主题机制（实现时复用）

- `ThemeMode { LIGHT, DARK, SYSTEM }` 枚举（`ui/theme/Color.kt`）
- `AppColors` 结构 + `LightAppColors`/`DarkAppColors` 两套值 + `LocalAppColors` CompositionLocal + `appColors` 扩展（Compose 内统一取色）
- 持久化：`LocalStore`（SharedPreferences）+ `MessageRepository.themeMode` StateFlow
- 渠道品牌色不随模式变化，保留在 `AppTokens` 中
- 系统通知 RemoteViews 无法用 Compose 取色，颜色须在构建时（`NotificationHelper`）按当前 `ThemeMode` 注入

## 三、任务一：消息弹窗（Expanded 卡片）——体积过大、布局不合理

### 现状规格

**窗口尺寸**：
- 宽度 = 全屏宽（`screenWidthDp`），卡片内容左右各留 12dp（`EXPANDED_HORIZONTAL_PADDING_DP`）
- 顶部下沉：状态栏底边以下 14dp（`EXPANDED_BELOW_STATUS_GAP_DP`）
- 单卡高度 = 固定 **184dp**（`OverlayCardHeight`）
- 容器总高 = `184 + 11×(n-1) + 16`（n = 卡片数，最多 5 张）

**单卡内部布局**（Row：左侧内容列 + 右侧按钮列）：
- 卡片：圆角 14dp、内边距 14dp、最前卡阴影 8dp（旧卡 4dp）

左侧内容列（自上而下）：
1. 状态行：9dp 状态色圆点 + 状态标题（14sp Bold，已完成/失败/等待等）+ 应用图标（19dp）+ 来源名（11sp 灰色）
2. 项目标题（14sp SemiBold，单行省略）
3. 任务日志内容（13sp、行高 18sp、**最多 4 行**、超长省略）← 高度主要占用
4. 弹性空隙（`weight(1f)`）
5. 页脚行：时间（10sp）‖ **token 用量**（10sp，仅 >0 显示，位于耗时左侧）‖ 耗时（10sp）

右侧按钮列（仅最前卡显示）：固定宽 **74dp**，"全部关闭"（28dp 高、11sp 小按钮）在上、"关闭"在下，纵向间距 8dp；**非最前卡右侧保留 74dp 空白占位**

**堆叠与交互**（最多 5 张）：
- 最新卡在最前完整显示且可交互；旧卡逐层下移 11dp、横向缩窄 2.6%/层（下限 0.88 倍），仍保留完整内容
- 向左滑动超过卡宽 28% 关闭最前卡（震动反馈 + 快速滑出动画），仅响应左滑，拖动中只更新图层位移/透明度
- 消息不自动标已读、不自动消失，必须用户显式关闭

### 问题清单

1. **卡片过高**：单卡固定 184dp——消息只有一两行时也占满；4 行日志上限 + 弹性空隙使卡片高度与内容量完全脱钩
2. **宽度过宽**：展开即全屏宽，左右仅 12dp 边距，视觉上"一大块"，与 Peek 胶囊（≤220dp）跳跃感强
3. **右侧按钮列浪费空间**：固定 74dp（约屏宽 1/5）只放两个小按钮；非最前卡还要空占位，压缩内容列实际可用宽度
4. **纵向信息密度失衡**：4 行日志 72sp 行高 vs 28dp 小按钮，卡片上下视觉重量不均；短消息时大量留白集中在日志区

### 优化方向

- 卡片高度改为**内容自适应**（按消息行数收缩，设合理 min/max），或压缩日志行数上限（如 2–3 行）并整体瘦身
- 展开宽度收窄（如 `min(全屏-边距, 固定上限)`），保留居中锚点
- 按钮列改横向紧凑排布、图标化，或并入卡片底部/页脚，消除 74dp 固定占用；旧卡去掉空白占位
- 页脚字段与按钮行的布局再平衡；保持 token 位于耗时左侧、仅 >0 展示的既定规则

## 四、任务二：流媒体胶囊（Peek）——恒深色改为跟随主题

### 现状规格

- **定位**：摄像头正下方横向胶囊（对齐 realme/ColorOS 充电流体云），常驻屏幕顶部实时展示最新任务状态，是新消息的默认入场形态
- **背景**：`AppTokens.IslandBackground = #0A0A0B`（近黑），全圆角（半径 = 胶囊高/2），阴影 8dp
- **内容**（横向排列，左右 padding = 胶囊高/2）：
  1. 状态圆点（7dp），**呼吸脉冲动画**（scale 1→1.45，900ms 往复）
  2. 应用名/摘要（12sp Bold，`IslandTextPrimary #EDEDEE`，单行省略）
  3. 未读数（10sp Medium，`IslandTextSecondary #8B8B90`，可无）
- **状态色**：Waiting 琥珀 `#FBBF24` / Completed·Approved 绿 `#4ADE80` / Failed·Stopped·Rejected 红 `#F87171`
- **触控壳**：比视觉胶囊宽（左右各 +18dp）、向下延伸到状态栏底边以下 36dp——保证整颗（含圆角外缘）可点，且不压摄像头孔
- **定位**：相对状态栏底边下移 4dp 挂在摄像头正下方；水平与挖孔中心对齐

### 核心问题

**胶囊恒为深色，不跟随应用深浅色模式**——`Color.kt` 注释原样写明："摄像头灵动岛（Dynamic Island）：恒深色，不随深浅色模式变化，贴合挖孔黑色观感"。即白天模式下这颗黑色胶囊也以近黑 `#0A0A0B` 显示，与浅色界面脱节。

### 优化要求

- **白天模式（LIGHT）**：胶囊背景换为**主题色（浅色系）**，文字/计数同步深色；状态色圆点（琥珀/绿/红）在浅色背景上需保证对比度（可能需加深）
- **夜间模式（DARK）**：保持现有暗色（或按暗色主题令牌微调）
- Compact 贴孔圆点背景同步跟随

### 实现路径

- `Island*` 系列令牌（`IslandBackground`/`IslandSurface`/`IslandBorder`/`IslandTextPrimary`/`IslandTextSecondary`）从 `AppTokens` 常量**并入 `AppColors`**，增加 light/dark 两套取值
- 消费点改走 `appColors`：
  - `ui/Island.kt`：`TapRelayIsland` 的 `AppTokens.IslandBackground`/`IslandTextPrimary`/`IslandTextSecondary`
  - `ui/TapRelayOverlay.kt`：第 186 行 `islandBackground = AppTokens.IslandBackground`（Compact/Peek 档共用）
- 状态色（IslandDone/Waiting/Error）也可一并纳入 AppColors 浅/深两套，保证浅底对比度

## 五、任务三：胶囊动态效果优化 + 省电设置开关

### 现状

胶囊动效单一：仅有状态点 900ms 呼吸脉冲（scale 1→1.45 往复）；三档形变有基础过渡动画（`IslandAnimations` MorphDp/MorphFloat/MorphColor）。

### 优化要求

1. **优化出好看的动态效果，让用户注意力集中到胶囊**——新消息到达、状态变化（等待/完成/失败）时应有更醒目的视觉反馈（如：新消息入场脉冲/波纹、状态色过渡、胶囊短暂高亮/微动等，具体设计自定，需在 Compose 内实现）
2. **动效耗电**：效果**默认开启**，但**用户必须在设置中可自行开关**（"开启动态效果"开关）
3. 关闭效果时：回到当前的基础动效（呼吸脉冲可保留或一并关闭，实现时定），仅保留必要的档位形变过渡
4. **设置项落点**：
   - `LocalStore` 新增持久化字段（参考现有 `loadThemeMode`/`saveThemeMode` 模式）
   - `MessageRepository` 新增 StateFlow（参考 `themeMode` 模式）
   - 设置区域 UI：现有 `ConnectionPanel` 已有 `overlayDebugEnabled` 调试开关的接入模式可参考；主界面顶栏有主题切换按钮

## 六、优化时必须遵守的硬约束（所有任务不得破坏）

- 单窗口三档形变（Compact→Peek→Expanded），禁止 `removeView/addView` 换窗口；窗口 `WRAP_CONTENT` + `FLAG_NOT_FOCUSABLE/FLAG_NOT_TOUCH_MODAL/FLAG_LAYOUT_IN_SCREEN`，水平对齐挖孔中心
- 新消息默认进 Peek；Compact 圆点不得作为入场默认；Peek 挂摄像头正下方（状态栏底边下 ~4dp）、高 28–36dp、宽 120~220dp（≤72% 屏宽），不压摄像头孔、不得退回状态栏拦截区；不得纵向拉成大黑球
- 整颗（含圆角外缘）可点；触控壳规则（左右 +18dp、向下 36dp 可点区）不得破坏
- Expanded 同锚点紧凑层叠，最多 5 张，仅最前卡可交互；旧卡不得丢失项目/日志内容
- 最前卡必须结构化显示：项目标题、任务日志、时间、右侧耗时；`tokenCount > 0` 时 token 在耗时左侧；"全部关闭"必须在"关闭"正上方（若保留双按钮）
- 左滑超 28% 关闭、仅左滑、拖动不触发布局重排；卡片区外触摸透传；缺悬浮窗权限静默降级普通通知
- 消息不自动标已读、不自动消失
- 颜色一律走 `Color.kt` 语义令牌（`AppColors`），UI 只用 Compose + Material3；渠道品牌色保持 `AppTokens` 不随模式
- 状态点呼吸脉冲动画保留（除非动效开关关闭）；系统通知 RemoteViews 颜色构建时按当前 `ThemeMode` 注入

## 八、验证要求（实施完成后）

- Android 单元测试通过：`.\gradlew.bat :app:assembleDebug :app:testDebugUnitTest`
- 真机/模拟器验证：
  1. 白天模式：胶囊为浅色主题、文字深色；消息弹窗、全屏提醒、系统通知均为浅色体系
  2. 夜间模式：胶囊为暗色、其余弹窗均为深色体系
  3. 模式切换瞬间所有弹窗形态同步变化，无残留恒色
  4. 新消息到达时胶囊动态效果出现；关闭开关后回到基础动效
  5. 三档形变、点击、左滑、触摸透传等既有交互不回归
