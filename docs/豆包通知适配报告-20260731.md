# 豆包通知适配报告（2026-07-31）

## 1. 任务范围

本次为 TapRelay 增加豆包桌面端任务通知适配，使豆包任务完成或失败后通过 PC 端固定端口 `1122` 推送到 Android，并在 Android 中以“豆包”独立渠道展示。

## 2. 环境与信号定位

- 豆包安装目录：`C:\Users\Admin\AppData\Local\Doubao\Application`
- 主程序：`C:\Users\Admin\AppData\Local\Doubao\Application\app\Doubao.exe`
- 实际日志目录：`C:\Users\Admin\AppData\Local\Doubao\User Data\sdk_storage\log`
- 任务事件文件：`saman_*.log`
- 可靠完成信号：豆包网络 SDK 对 `/chat/completion` 请求写出的最终 `[rlog]`

真实任务验证中，豆包成功完成两条“只回复指定文本”的请求；最终日志包含 `req_id`、`ret=Ok(200)`、`base.status=SUCCESS`、`response.code=200`。另一次长任务被用户取消，最终日志为 `ret=Err(Msg("request canceled"))` 且 `base.status=IO_PENDING`。

## 3. 实现规则

### 3.1 PC 日志监听

新增监控目录：

```text
%LOCALAPPDATA%\Doubao\User Data\sdk_storage\log
```

新增测试/便携部署覆盖变量：

```text
TAPRELAY_MONITOR_LOCALAPPDATA
```

仅接受完整目录中的 `saman_*.log`，不处理豆包其他目录下的普通日志。

### 3.2 事件解析

只解析同时包含以下标记的日志行：

```text
[rlog]
req_id=
request_log=
```

并要求 `request_log.base.origin_url` 包含 `/chat/completion`。

| 条件 | TapRelay 结果 |
|---|---|
| `ret=Ok(...)`、`base.status=SUCCESS`、HTTP `2xx` | `source=doubao,status=completed` |
| 非取消错误、非 SUCCESS 或非 `2xx` | `source=doubao,status=failed` |
| `request canceled/cancelled` 或 `base.status=IO_PENDING` | 忽略，不发送通知 |
| 非 `/chat/completion` 请求 | 忽略 |

任务标识使用豆包网络请求的 `req_id`：

```text
taskId = req_id
cwd = ""
```

当前豆包日志中未发现可靠工作目录，因此不伪造 `cwd`。

### 3.3 Android 渠道

Android 新增：

```text
source=doubao -> 豆包
颜色：#F56548
标识字母：D
```

消息继续沿用全应用唯一 ID 规则 `source|status|taskId`。

- 豆包真实服务端失败已人为复现。本次失败分支通过解析测试和 E2E 注入验证。
