## 0. 执行摘要

TapRelay 是一套**本地优先（local-first）的局域网任务通知中继**：Windows PC 上的 AI Agent / 桌面工具 / 脚本把任务完成、失败、等待处理等事件，经 `http://localhost:1122/send` 送达 PC 内置服务，再由 WebSocket 推送到 Android 手机；手机可对 `waiting` 任务做远程审批并停止可控任务，不提供继续会话或发送新指令入口。项目**刻意不做**账号、云端存储、公网推送、鉴权与离线补发（见 `04-核心铁律与避坑.md` R1/R3/R6/R8）。

项目由四个可交付组件构成（边界固定见 `03-目录与架构规范.md` R1 与 `CLAUDE.md` R3）：
- `pc-app`（C# / WinForms，.NET 3.1）—— 正式入口与生产服务，**日常使用只跑这一个**
- `notify-server`（Node.js 24）—— 协议开发与 Vitest 自动化测试入口，**非日常必启**
- `android-app`（Kotlin / Jetpack Compose）—— 手机客户端
- `.zcode/skills/{notify-phone, adapt-app}` —— ZCode/Codex 触发器与通用适配技能

审计确认：**构建配置与编号规则高度一致**（Node/Android/PC 版本、依赖、端口均吻合规则）；**架构分层清晰**（Android 严格 `ui/service/notification/data` 分层、单一状态源 `MessageRepository`）；**规则体系完整**（CLAUDE.md + 01–11 编号文件 + 09 问题库，P001–P099）。

需重点关注的**架构张力 / 待澄清项**（详见第 9 节）：
1. 规则入口 `AGENTS.md` 与 `CLAUDE.md` 并存且各自自我引用（规则 R2 只允许 AGENTS.md + NN 文件）。
2. **端口漂移真实矛盾**：`04` R2 规定端口固定 1122，但 `NotifyServer.cs` 有 `FindAvailablePort` 自动切端口，而 Android 端 `ServerConfig.DEFAULT_PORT` 硬编码 1122——PC 切端口后手机会连不上。
3. `qwen` 图标/键残留与黑名单并存、`linuxdo_cdk` 已适配但未回填规则文档。
4. 协议双实现（Node + C#）的字段归一维护负担。
5. 多个 >95KB 巨型源文件带来的可维护性风险。

## 1. 项目定位与业务链路

固定链路（`CLAUDE.md` R4、`README.md`、`06-通信与数据获取规范.md`）：

```
Agent / Hook / 本地日志  ──POST /send──▶  TapRelay PC (内置 HTTP+WS 服务, 端口 1122)
                                          │
                                          ├──WS 广播──▶  Android (WebSocketService)
                                          │                  └─ 系统通知 / 浮窗 / 全屏 / App 列表
                                          └──/apps/register、/apps/icon──▶ Android 应用目录同步
Android (waiting/可停止任务)  ──WS control──▶  PC (审批回传 / 停止任务)
```

- **零配置铁律**（`04` R1）：服务自启、端口默认 1122、隧道自动检测、防火墙自动放行（`FirewallHelper`）、开机自启（`AutoStartHelper` 写 HKCU Run）、权限向导引导。
- **不擅自加鉴权**（`04` R3）：无 token / 配对 / 登录。
- **即时送达、无离线补发**（`04` R8、`08` R5）：无在线客户端即丢弃，不排队、不重连补发。

## 4. 模块依赖关系与关键业务流

### 依赖方向（规则 `03` R4 固化）
```
Android:  ui ──▶ data ;  service ──▶ data ;  service ──▶ notification ;  MainActivity ──▶ ui/service
          data 层禁止引用 Compose/Activity/Notification API
PC:       MainForm ──▶ NotifyServer + 各 Monitor/Adapter ──▶ BroadcastFromMonitorAsync ──▶ WS 广播
```

### 关键业务流 A：Agent 任务完成 → 手机
```
WorkBuddy 写 awaiting_input / Stop 事件
  → Program.cs(--codex-notify) 或 AgentCompletionMonitor(FileSystemWatcher)
  → NotifyServer.CreatePayload (status/source/taskId/sessionId/taskLog/durationMs/tokenCount)
  → WS broadcast(clients)  → Android WebSocketService 解析
  → MessageRepository.appendMessage + NotificationHelper / OverlayCards
```

### 关键业务流 B：手机远程审批（waiting → PC）
```
PC 广播 type=event approval.requested (requestId)
  → Android 显示 允许/拒绝 (hasApprovalAction)
  → WS control {action:approval.resolve, requestId, decision}
  → PC NotifyServer.HandleControl → pendingApprovals.resolve
  → /events HTTP 返回 resolved → 广播 approval.resolved
  → (WorkBuddy) ResolveWorkBuddyWaiting：置前窗口 + SendKeys
```

### 关键业务流 C：手机停止可控任务
```
Android 发 agent.call {session.stop, agentKey, sessionId}
  → PC NotifyServer → 对应 AgentProxy 停止当前任务
  → 回执 agent.result
```

## 5. 协议与数据模型

**请求端点**（`06` R1/R2/R4/R7/R8）：
- `POST /send`：`message`(必填, ≤500)、`taskLog`(≤4000 UTF-16)、`source`/`status`(`completed|failed|waiting`)/`taskId`/`sessionId`/`cwd`/`projectName`/`durationMs`/`tokenCount`/`credits`/`notificationTitle`/`actionUrl`/`requestId`
- `POST /events`：`eventType`(白名单)、`approval.requested` 同步等手机回写
- `GET /health`：`{status,port,clients}`
- `GET /apps`、`POST /apps/register`、`GET /apps/icon/<appKey>`：动态应用目录（不覆盖内置键）

**WebSocket 推送载荷**：`type=message|event`；`heartbeat`↔`heartbeat_ack`；`control`(approval.resolve / agent.call)。时间均为带时区 ISO 8601（`message.js` `formatIsoWithOffset`）。

**Android `NotifyMessage` 去重键**（`Models.kt`）：`eventId` → `source|status|taskId` → `time|type|content`；历史≤100，UI key 唯一（`ensureUniqueMessageIds`，P003）。

**持久化边界**：服务端仅内存 + 应用注册表（落盘 `LOCALAPPDATA\LanNotify`）；**不保存业务消息历史**（R6/`08` R5）。Android 仅 SharedPreferences。

## 8. 编码约定（已落地，供后续优化遵守）

1. **中文 UI + 英文 ASCII 标识符**（`01` R5）：类名/函数名/JSON 字段全英文，用户可见文案中文。
2. **真实日志优先**：禁止"任务已完成/需要确认"等模板冒充 `taskLog`/`message`（`06` R3/R10、`11` R4）。

4. **状态源唯一**（Android `MessageRepository`）、**数据层不反向依赖 UI**。
5. **双实现字段归一**：Node `message.js` 与 C# `NotifyServer.CreatePayload` 必须同步（P074 已踩坑）。
6. **测试强制**：`npm test` / `gradlew testDebugUnitTest` / `dotnet` 测试；改服务端必跑 `npm test`、改 Android 必跑单测（`01` R4）。
7. **发布门禁**：git push 前 CPU/Mem 检查（`04` R10）；PC 打包走 `package-pc.ps1`（`04` R9）。
8. **安全边界**：不传密码/令牌/完整敏感参数；`taskLog`/审批摘要先脱敏（`README` 数据边界）。

  - `docs/PROJECT_OVERVIEW_FOR_AGENTS.md` 两处"端口冲突自动切换"措辞改为"固定端口 1122（铁律 R2，不漂移不切换）"。
